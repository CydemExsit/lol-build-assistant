# 新對局裝備推薦效能

自動偵測新對局後，鞋子、熱門裝備與高勝率裝備統計共用一次 Chromium 啟動及頁面載入。各份 LoLalytics 快取獨立判斷效期，預設 6 小時；摘要過期不會連帶強制更新仍有效的其他資料。缺少、損壞或過期的資料才會重新取得。

同次推薦依路線類型重用鞋子評分，非多路線英雄略過不必要的全套裝類型掃描。套裝來源、候選門檻、評分政策及本場凍結行為維持一致。

## 實測範圍

2026-10-17，同一台 Windows 電腦，以同一場 Ashe 十人陣容及分開的空快取目錄量測實際資料取得與推薦計算。

| 項目 | 修改前 | 修改後 |
| --- | ---: | ---: |
| 無快取的資料取得與推薦計算 | 30.400 秒 | 11.175 秒 |
| 三份統計使用的瀏覽器頁面載入 | 3 次 | 1 次 |

這組單場測量耗時減少 63.2%，前後各執行一次，結果受網路與站點狀況影響，不能推論為所有英雄的固定加速幅度。前後取得的 2,168 筆套裝、9 筆鞋子、各 46 筆熱門／高勝率裝備及最終三條路線完全一致。

另以新取得的完整有效快取，使用既有十人陣容與複製的歷史資料庫重播自動流程 7 次：從辨識對局、保存快照、計算，到寫出 JSON／Markdown／歷史並凍結方案，中位數為 0.088 秒，未連網或啟動瀏覽器。這項時間不含對局偵測輪詢（預設 3 秒）與網頁更新輪詢（2.5 秒）。

六場既有快照也以相同舊快取離線比對，推薦輸出一致，僅忽略隨時間變動的資料年齡。該比對明確使用原有 168 小時效期，以比較相同資料；產品預設仍為 6 小時。

## 調整與驗證

```powershell
python -m src.main watch --cache-max-age-hours 6
python -m src.main watch --refresh-lolalytics
python -B -m pytest -q -p no:cacheprovider
node --check web/app.js
```

強制更新選項會略過快取。方案完成後會凍結，後續快取更新不會改動本場方案。測試涵蓋獨立效期、缺少／損壞資料重建、部分統計失敗及新對局只處理一次；CI 在 Windows、Linux 與 Python 3.11／3.13 執行離線測試。測量原始快取、對局與歷史資料保留在本機，不納入 Git。
